## 0. 每项执行前

- [ ] 核对工作区、当前 spec/源码、已有测试和最新可访问 CI 结果；记录证据，已覆盖项直接复用。
- [ ] 明确该项支持范围、责任人、依赖、输入、断言和失败标准；涉及新承诺时先更新对应 spec/delta 与 Scenario→测试映射，再实现。
- [ ] 代码大改前建立全量构建基线；沿用 JDK 21、真实 Maven、DB fork 参数及共享数据库串行规约。

## 1. P0 / PA-01 独立金额与对账

- [ ] 以目录价格、用量和操作时间线建立独立案例集：固定周期、比例计费、用量阶梯边界、目录生效、贷项/部分支付及币种舍入；逐项说明来源和预期。
- [ ] 增加真实 WAR 的独立预期断言；比对发票项、期间、币种、总额、已付与余额，保留重启校验。
- [ ] 定向改变金额/期间等保护条件，确认验收断言失败后还原；保存原始报告。

## 2. P0 / PA-02 支付结果未知与恢复

- [ ] 复核 TestPaymentApi/TestJanitor/重试测试，列出已有覆盖和 LPR 真实调用链仍缺的场景；选定首个目标网关及其幂等契约。
- [ ] 建立插件外部、可持久查询的受控网关账本及故障屏障，模拟扣款提交后丢响应；核对重试/重启与本地未知状态恢复，不用“超时=未扣款”推断。
- [ ] 验证同一业务操作重放、重复/乱序通知、退款响应丢失；按网关契约核对操作标识、资金次数/金额及本地交易/发票结果，不把消息 UUID 去重当作通用支付幂等。
- [ ] 使用目标网关沙箱复核关键路径，保存脱敏远端交易证据；缺凭据或能力时明确待外部条件及未覆盖部分。
- [ ] 临时破坏去重/恢复等保护条件，确认相应测试能检出；恢复后执行相关回归。

## 3. P0 / PA-03 在途支付升级与回滚

- [ ] 明确旧请求完成/失败方式、超时后状态、停止预算及资源释放时机；对照当前实现，以可复现失败决定是否需要改实现。
- [ ] 在旧版请求已进入网关但尚未返回时激活新版，再分别完成旧请求、制造超时及触发健康回滚；通过真实 WAR/平台调用链记录请求→插件版本→网关操作→本地交易。
- [ ] 分别断言候选启动失败保留旧版、新请求正确路由、旧请求结果符合契约、无重复资金效果及旧版最终资源释放；Registry 非空不能单独判通过。
- [ ] 对切换/旧请求处理/资源关闭的关键守卫做定向变异，观察失败并还原；执行运行时、隔离、泄漏及 TestKit 回归。

## 4. P1 / PA-04 独立复现与业务等价

- [ ] 在独立 Linux CI 对确定提交执行已有及新增验收，保存原始报告与制品摘要；区分构建、测试、静态跳过项及外部凭据受限步骤。
- [ ] 选择并记录可比历史提交、依赖、配置、DB 初始数据及请求序列；比较目录/订阅/发票/支付结果，ID 等归一化不得隐藏业务差异。无可比基线时说明原因并使用独立预期值。
- [ ] 历史差分与独立金额/网关证据交叉验证，记录历史实现共有缺陷及差异处置，不将“与旧版一致”直接等同正确。

## 5. P1 / PA-05 容量与长稳

- [ ] 执行前固定硬件、负载、资源预算、时长、升级轮次、采样方式及通过阈值；先记录基线，区分业务预期失败与运行时引入失败。
- [ ] 结合持续请求与反复升级/回滚，记录吞吐、p95/p99、错误、线程/连接、堆及 Metaspace；使用 JFR/jcmd/引用分析定位异常趋势。
- [ ] 输出可复现命令、原始时序和结论适用范围；超阈值则形成具体缺陷待办，不以一次 GC 或瞬时内存下降判定长期无泄漏。
