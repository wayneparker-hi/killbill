# 设计

- 共享调度器继续使用既有 activeQueues 引用计数；非最后一个停止只代表逻辑停用，返回成功，不声称已等待全部 handler。
- 最后一个队列保留关闭顺序及各阶段超时返回值，不通过删日志或增加超时掩盖失败。
- 完成线程在停止后继续消费已入队记录；生产者 handler 的等待保持在完成线程停止之前。
- 门闩控制实际 handler 和完成批次，避免靠睡眠猜测并发时序。超时用独立配置缩短预算，最终释放门闩并清理线程。
- PostgreSQL 测试只使用验收工具新建的独立数据库；队列名随机化，重启复用同库；现有共享库和 Redis 业务键不变。
- 每个故障对照只改变被检验条件；保留至少一次语义，不把正常重启不重复外推为崩溃 exactly-once。
