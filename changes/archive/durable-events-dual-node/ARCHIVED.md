## 结果与边界

同机双 JVM 使用不同队列节点标识，在同一独立 PostgreSQL 数据库验证正常竞争消费及确认前强制终止后的接管。正常场景 12 个 UUID 各一次投递；故障场景原 UUID 跨节点重放，业务效果去重为一份。

修正初版测试的父子 JVM 时区不一致及租约断言口径，保留未检出变异的诊断记录。本轮无生产 Java、POM、公共 API 或装配改动。

不覆盖跨主机网络、任意 SQL 交错、失效租约 fencing、数据库服务端故障或远端 Linux CI；保持至少一次语义，不推导为 exactly-once 或公平分配保证。

# 双节点持久化插件事件验证

## Why

既有 PostgreSQL 进程故障测试先停止旧 JVM 再启动新 JVM，未验证两个运行中节点共用队列表。需要以实际竞争、owner 和恢复证据界定现有能力，避免凭代码推断支持。

## What Changes

- 两个独立 JVM 使用不同 CreatorName、相同订阅和同一独立 PostgreSQL 数据库，运行生产 adapter/DAO/reaper。
- 验证有效 claim 内的正常竞争消费，以及两节点同时在途时强制终止一方后由存活节点恢复。
- 保存每节点投递、owner、退出码和消息状态；纳入已有验收入口。
- 仅有可复现生产缺陷才修改生产代码；不预设需要新锁、选主或调度功能。

## Impact

测试与验收范围，不新增公共契约、生产依赖或装配；不承诺公平分配、全局顺序、exactly-once、失效租约 fencing、跨主机或数据库故障恢复。
